# Cloudflare Tunnel и Zero Trust Access

## Состав каталога

| Файл | Назначение |
|---|---|
| `desired-state.json` | Желаемое состояние: зоны, имена хостов, туннель, политика доступа. Единственное место, где это описано. |
| `CfApi.psm1` | Слой доступа к API. По умолчанию умеет только читать. |
| `preflight.ps1` | Проверка готовности. Только чтение, ничего не меняет. |
| `apply.ps1` | Настройка. Без ключа `-Apply` показывает план и ничего не меняет. |
| `config.sample.yml` | Образец `/etc/cloudflared/config.yml` для узла. |

## Порядок работы

```powershell
# Токены: один на зоны (DNS, настройки), второй на аккаунт (туннель, Access).
$env:CF_ZONE_TOKEN = '<токен зон>'
$env:CF_ACCOUNT_TOKEN = '<токен аккаунта>'

.\preflight.ps1 -IncludeUnmanaged   # готовность; код возврата 1 = запускать нельзя
.\apply.ps1                          # план, без изменений
.\apply.ps1 -Apply                   # применение
```

Токены разделены не для удобства: права на туннель существуют только на уровне
аккаунта, а права на DNS — только на уровне зоны, и одним токеном обе задачи не
закрываются без выдачи лишнего.

## Почему изменения защищены двумя способами

Первый: `CfApi.psm1` отклоняет любой метод, кроме GET и HEAD, пока предохранитель
не снят, а снимает его только `apply.ps1` с ключом `-Apply`. Ошибка в коде проверки
состояния поэтому не способна ничего изменить в аккаунте.

Второй: `apply.ps1` сначала запускает `preflight.ps1` и отказывается работать, если
есть блокирующие пункты. Это не формальность — записи в зоне, делегирование которой
ещё не переключено, выглядят как успешная настройка, но не отвечают.

Все шаги идемпотентны: скрипт ищет существующий объект и создаёт его только при
отсутствии. Повторный запуск на настроенном аккаунте даёт пустой план.

Политика Access не создаётся, если список адресов пуст: такая политика открыла бы
вход всем, что хуже, чем отсутствие приложения. Скрипт останавливается с ошибкой.

Фактическое состояние на 16.08.2026 и что мешает запуску:
`docs/audit/cloudflare-readiness-2026-08-16.md`.
Что должен сделать владелец руками: `docs/design/dns-cloudflare-setup.md`.

## Что это даёт

Туннель устанавливает исходящее соединение от узла к Cloudflare, поэтому на
сервере не нужно открывать ни одного входящего порта. Публично адресуемым
становится только имя в вашей зоне, а сам узел остаётся невидимым для сканеров.

Access добавляет проверку личности до того, как запрос дойдёт до приложения.
Это закрывает главный пробел стокового electerm-web: в нём один общий пароль на
всех, без учётных записей и журнала. С Access у каждого сотрудника свой вход с
MFA, а отзыв доступа делается в одном месте.

## Порядок настройки

1. Домен переносится в зону Cloudflare, DNS обслуживается Cloudflare.
2. В Zero Trust создаётся туннель, его идентификатор и файл учётных данных
   кладутся на узел в `/etc/cloudflared/`.
3. `config.yml` берётся из `config.sample.yml`, подставляются `tunnel` и имя хоста.
4. Служба включается: `cloudflared service install`, затем
   `systemctl enable --now cloudflared`.
5. В Zero Trust создаётся приложение типа Self-hosted на то же имя хоста и
   политика доступа: разрешить конкретные адреса электронной почты или группу,
   обязательный второй фактор.
6. Из настроек приложения берутся `AUD` и `team domain` и прописываются в `.env`
   узла как `CF_ACCESS_AUD` и `CF_ACCESS_TEAM_DOMAIN`.

## Почему приложение обязано проверять JWT само

Access ставит подписанный JWT в заголовок `Cf-Access-Jwt-Assertion`. Если
приложение его не проверяет, а просто доверяет тому, что «мы за туннелем», то
любой, кто сумеет обратиться к порту приложения напрямую (изнутри узла, из
контейнера, через ошибку в конфиге туннеля), получит полный доступ без входа.
Поэтому проверка подписи по публичным ключам
`https://<team>.cloudflareaccess.com/cdn-cgi/access/certs` и сверка `aud`
делается в самом приложении. Это же даёт нам имя пользователя для прав доступа
внутри платформы.

## Что не покрывает Access

Access защищает HTTP. Прямые RDP, SSH и VNC к целевым машинам он не закрывает --
для них нужен меш WireGuard, а на самих машинах доступ ограничивается подсетью
меша.
