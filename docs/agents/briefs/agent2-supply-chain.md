# Бриф: Агент 2, аудит цепочки поставок

## Контекст

Мы строим командную платформу удалённого доступа на базе форка electerm-web.
Требование владельца: убрать всё, что подтягивается из неофициальных источников,
и закрепить версии всего остального. Полной гарантии чистоты чужого кода не
бывает, поэтому цель реалистичная: получить полный перечень внешних загрузок,
понять для каждой первоисточник и способ фиксации, и выявить исполняемый код,
который запускается в обход явной установки.

## Что именно искать

1. Загрузки мимо GitHub: скрипты установки на сторонних доменах, обращения к CDN,
   зеркала. Известный пример, с которого стоит начать: README electerm-web
   предлагает `curl -o- https://electerm.org/scripts/one-line-web.sh | bash`.
   Нужно выяснить, что этот скрипт делает и что скачивает.
2. Пакеты npm с `preinstall`, `install`, `postinstall` в `package.json`, а также
   пакеты, которые при установке тянут prebuilt-бинарники (типичное для нативных
   модулей: node-pty, ssh2 с криптографией, sqlite-биндинги). Для каждого —
   откуда именно скачивается бинарник.
3. Обращения к сети во время работы приложения: телеметрия, проверка обновлений,
   эндпоинты ИИ по умолчанию, синхронизация закладок во внешние сервисы
   (github/gitee gist), любые «домашние» адреса в коде и конфигах.
4. Docker-образы, указанные по тегу вместо digest, и базовые образы неизвестного
   происхождения.
5. Файлы, попавшие в репозиторий в собранном виде: минифицированный JS, wasm,
   исполняемые файлы, архивы. Для них нужно указать, воспроизводима ли сборка из
   исходников в том же репозитории.

## Границы допустимых действий

Разрешено: клонировать репозитории, читать файлы, скачивать архивы и распаковывать
их для чтения, считать хеши, обращаться к реестру npm и GitHub API за метаданными.

Запрещено:

- запускать любой скачанный код, включая `npm install`, `npm ci`, `cargo build`,
  установочные `.sh` и `.bat`, docker-образы. Установка npm-пакетов выполняет
  их `postinstall`-скрипты, то есть равнозначна исполнению чужого кода;
- вносить скачанный чужой код в репозиторий;
- менять что-либо за пределами разрешённых путей.

Разрешённые для записи пути: `docs/audit/`, `security/`.

## Формат результата

1. `docs/audit/supply-chain.md` — отчёт для человека. По каждой находке:
   что это, где именно (файл и строка), откуда качается, чем это опасно,
   и предлагаемое решение с вердиктом «оставить как есть / заменить официальным
   источником / закрепить версию / вырезать».
2. `security/externals.json` — машиночитаемый реестр по схеме, описанной в
   `security/README.md`. Он будет использоваться проверкой в CI, поэтому важны
   точные имена и версии, а не описания.
3. Отдельным разделом отчёта: список того, что проверить не удалось, и почему.
   Честный список пробелов важнее, чем видимость полного покрытия.

## Критерий готовности

Для каждой строки `package.json` основного проекта известно, откуда берётся код
при установке, и указан способ его закрепления. Все сетевые адреса, найденные в
исходниках, перечислены в отчёте с пометкой, нужны они в работе или нет.
