## Что обнаружено в исходниках

Разбор проводился чтением кода на указанном коммите. Полный аудит цепочки
поставок с транзитивными зависимостями — отдельная работа, см. `docs/audit/`.

### Установка пакетов npm во время работы приложения

`src/app/lib/npm.js` содержит собственный установщик: запрашивает
`https://registry.npmjs.org/<пакет>/latest`, скачивает архив и рекурсивно ставит
зависимости. `src/app/lib/custom-require.js` использует это так: если `import`
модуля не удался, модуль скачивается из реестра и сразу исполняется через
`import()`.

Это самый серьёзный из найденных механизмов: код появляется на сервере в обход
lock-файла, сборки и ревью, причём всегда версии `latest`, то есть результат
зависит от того, что опубликовано в реестре в момент запуска.

Существенная оговорка: в этом репозитории `customRequire` не вызывается ни из
одного места. Возможность есть, активного пути к ней в web-версии нет. Риск
скрытый, а не действующий, но он оживёт при первом обновлении upstream или при
подключении плагинов.

Решение: докачивание разрешено только при явном `ALLOW_RUNTIME_NPM_INSTALL=1`,
которого в нашем окружении нет. Дополнительно закрывается egress-файрволом.

### Обращения к внешним ИИ-сервисам по умолчанию

`src/app/lib/view.js` передаёт клиенту предустановленного провайдера
`https://ai.electerm.org/api/ai`, помеченного «default free».
`src/app/common/default-setting.js` содержит `https://api.atlascloud.ai/v1` с
моделью `deepseek-chat`.

Опасность здесь не в самом наличии ИИ, а в содержимом: в терминал попадают
команды, пути, фрагменты конфигов и иногда секреты. Отправка этого третьей
стороне по умолчанию для командной работы неприемлема.

Решение: адрес по умолчанию пуст, провайдер задаётся администратором через
переменные окружения `AI_BASE_URL`, `AI_MODEL`, `AI_API_PATH`, `AI_AUTH_HEADER`.

### Срок жизни токена 120 лет

`src/app/lib/jwt.js`: `expire = process.env.TOKEN_EXPIRED_TIME || '120y'`.
Токен подписывается `SERVER_SECRET`, механизма отзыва нет. Утёкший токен даёт
доступ навсегда, и единственный способ его аннулировать — сменить секрет, то
есть разлогинить всех.

Решение: значение по умолчанию 12 часов. Полноценный отзыв появится вместе с
многопользовательским режимом, где сессии будут храниться в базе.

### Аутентификация одним общим паролем

`.sample.env` показывает модель доступа: `SERVER_USER=default_user`,
`SERVER_PASS=1`, то есть один пользователь и один пароль на всех. Это и есть
причина, по которой нужен этап многопользовательскости: без него нет ни личных
учётных записей, ни журнала действий, ни возможности отозвать доступ у одного
сотрудника.

### Lock-файл рассинхронизирован с package.json

Попытка воспроизводимой установки командой `npm ci` на пине падает:
`Missing: @types/react@19.2.18 from lock file`. То есть штатным способом
собрать проект из закреплённых версий нельзя, остаётся `npm install`, который
разрешает зависимости заново в момент сборки — а значит две сборки из одного
коммита могут дать разный код.

Дополнительно в дереве есть конфликт peer-зависимостей: `vite@8` требует
`@types/node@26`, а закреплён `22.9.3`. Конфликт касается только типов времени
сборки и на исполняемый код не влияет, но без `legacy-peer-deps` npm
отказывается ставить дерево вообще.

Решение: lock-файл пересобран нами в контейнере целевой платформы и стал нашим.
Флаг `legacy-peer-deps` зафиксирован в `.npmrc`, чтобы локальная сборка и сборка
образа давали одинаковый результат.

### Клиентская часть приходит готовым пакетом

Шаг сборки `build/bin/install.js` копирует интерфейс из npm-пакета
`@electerm/electerm-react` в `src/client`. То есть весь фронтенд поставляется
собранным пакетом, а не собирается из исходников этого репозитория. Проверка
соответствия пакета его исходникам в наш контур не входит и остаётся известным
пробелом; фиксируем как ограничение.

### Что уже есть в upstream и не нужно делать заново

В зависимостях версии 5.1.20 присутствуют `ironrdp-wasm` (RDP в браузере через
WebAssembly), `@novnc/novnc` (VNC в браузере), `spice-client`, `@electerm/ssh2`
(собственный форк ssh2), `@electerm/ftp-srv`, `electerm-sync`. Отдельно есть
встроенный MCP-сервер (`src/app/widgets/widget-mcp-server.js`), выдающий наружу
набор инструментов.

Практический вывод: протокольные интеграции в значительной части уже сделаны
автором, и наша работа сводится к их настройке, проверке и ограничению, а не к
написанию с нуля. Встроенный MCP-сервер требует отдельного внимания: он даёт
программный доступ к возможностям приложения и в командном режиме должен быть
либо выключен, либо ограничен правами.

## Наши изменения

Изменения держим точечными и на явных швах, чтобы обновления upstream
подтягивались без разбора конфликтов по всему коду.

| Файл | Изменение |
|---|---|
| `src/app/lib/custom-require.js` | докачивание модулей из npm только при `ALLOW_RUNTIME_NPM_INSTALL=1` |
| `src/app/lib/view.js` | провайдер ИИ по умолчанию отключён, задаётся переменными |
| `src/app/common/default-setting.js` | убран сторонний адрес ИИ из настроек по умолчанию |
| `src/app/lib/jwt.js` | срок жизни токена по умолчанию 12 часов вместо 120 лет |
| `.npmrc` | `ignore-scripts`, точные версии |
| `Dockerfile` | своя сборка: база по digest, нативные модули из исходников, запуск не под root |

Диффы продублированы в `patches/` этого репозитория, чтобы их можно было
читать в ревью до появления форка на GitHub.

## Проверка сборки

Образ собран и запущен 15.08.2026, `electerm-platform:5.1.20-clean`, 452 МБ.

| Проверка | Результат |
|---|---|
| Сборка из lock-файла с запретом скриптов пакетов | проходит |
| Нативные модули собираются из исходников | `node-pty`, `@serialport/bindings-cpp` |
| Приложение поднимается, отвечает на HTTP | 200, страница отдаётся |
| Процесс работает не под root | пользователь `node` |
| `ai.electerm.org` в отдаваемой конфигурации | отсутствует |
| `api.atlascloud.ai` в отдаваемой конфигурации | отсутствует |
| Провайдер ИИ по умолчанию | `id: disabled`, адрес пуст |
| Срок жизни выдаваемого токена | 12 часов |

Найденная при сборке особенность: приложению нужен на запись каталог `/app/data`
(в нём же создаётся `uploads`), а не `/app/database`, как можно было
предположить по структуре проекта. Под непривилегированным пользователем
каталог не создаётся сам, поэтому он готовится в образе, и том монтируется
именно туда.
