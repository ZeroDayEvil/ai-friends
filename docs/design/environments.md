## Тестовая Windows-цель (Google Cloud)

| Параметр | Значение |
|---|---|
| Имя | `instance-20260815-212116` |
| ОС | Windows Server 2025 Datacenter, сборка 26100 |
| Ресурсы | 2 vCPU, 7 ГБ RAM, диск 100 ГБ |
| Внешний адрес | `35.208.225.47` |
| Внутренний адрес | `10.128.0.2/20`, шлюз `10.128.0.1` |
| Домен | нет, `WORKGROUP` |
| Часовой пояс | `Greenwich Standard Time` |

Настроено:

- OpenSSH Server запущен, автозапуск, вход только по ключу
  (`PasswordAuthentication no`, `MaxAuthTries 3`, `LoginGraceTime 30`);
- оболочка sshd по умолчанию — PowerShell, а не `cmd.exe`;
- публичный ключ администратора лежит в
  `C:\ProgramData\ssh\administrators_authorized_keys`, потому что для членов
  группы Administrators sshd на Windows игнорирует `authorized_keys` в профиле;
- псевдоним `winsrv` в `~/.ssh/config` на машине оркестратора.

Известные особенности и риски:

- RDP на 3389 открыт в интернет и принимает пароль. Решение владельца — оставить
  так на время тестов, машина одноразовая. На боевом узле так делать нельзя.
- Роли RDS не установлены, режим `LicensingType = 1`, то есть максимум два
  административных сеанса. Установка RD Session Host потребует перезагрузки и
  запустит 120-дневный льготный период.
- Служба `GCEAgent` остановлена, поэтому сброс пароля из консоли GCP недоступен.
  Аварийный путь при потере доступа — пересоздание машины.
- Не в домене, поэтому развёртывание RDS через мастер с Connection Broker
  недоступно: работать будет только автономный Session Host.

## Машина оркестратора

Windows-хост с публичным адресом `88.99.219.110`, экран 1920x1080 при
масштабировании 125%. Docker 29.5, Node 26.3, git 2.54. Установлен предыдущий
тестовый стек electerm-web с Caddy в `C:\remote-access` — он остаётся до
переноса на VPS и в дальнейшем подлежит удалению.

Важно для автоматизации GUI на этой машине: процессы без DPI-осведомлённости
получают виртуализованные координаты 1536x864 и обрезанные снимки экрана. Любой
скрипт, работающий с координатами, обязан вызывать `SetProcessDPIAware`.
