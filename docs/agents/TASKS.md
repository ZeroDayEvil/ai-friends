## Что готово к применению

Всё, что можно было сделать без внешних ресурсов, сделано и проверено:

- образ платформы собирается из закреплённых версий, запускается, внешние
  ИИ-эндпоинты в нём отключены, токен живёт 12 часов вместо 120 лет;
- режим Cloudflare Access реализован и проверен: без действительного токена
  приложение отвечает 401 на любой запрос, включая WebSocket;
- подключение к чужой сессии по её идентификатору закрыто;
- подключиться к чужой сессии по её идентификатору нельзя, а право сотрудника на
  конкретную машину проверяется на сервере, а не берётся из запроса клиента;
- скрипты развёртывания узла и меша проверены на синтаксис, compose-файл
  проверен, порт приложения привязан только к loopback;
- на тестовом сервере WinRM отключён вместе со службой и слушателями, включена
  NLA, отключён SMBv1, настроены аудит входов и блокировка учётной записи;
- доступ по SSH не зависит от единственного правила брандмауэра, а подъём узла
  после перезагрузки проверен на практике.

Тесты форка: 38 проверок в четырёх файлах, запуск `npm run test:platform`.

Порядок развёртывания, когда появятся ресурсы: `docs/design/runbook.md`.

## Что нужно от владельца инфраструктуры

Эти пункты нельзя закрыть агентами:

1. Тариф GitHub Pro либо осознанное решение работать без защиты ветки.
   Репозиторий создан, история выложена, CI проходит, задачи перенесены в issues.
   Включение защиты `main` отвечает 403 и требует именно GitHub Pro: подписка
   Copilot тарифицируется отдельно и прав на приватные репозитории не даёт.
   Разбор вариантов в issue #10.
2. Выделенный Linux-сервер под панель (Ubuntu 24.04, 2 vCPU, 4 ГБ RAM, 60-80 ГБ
   SSD), root по ключу. Заказан, ожидается выдача. Существующий
   `202.155.8.133` для этого не подходит по причинам из строки `vps-infra`;
   доступ по ключу к нему настроен, алиас `vps`.
3. Домен в зоне Cloudflare и аккаунт Zero Trust. Конкретно: включить Zero Trust и
   сообщить team name, добавить `anubis.locker` и `vpn-service-api.tech` в
   Cloudflare со сменой NS, исправить glue `ns2.hydradns.click` (сейчас
   `127.0.0.1`), дать список адресов почты сотрудников для политики Access.
   Подробнее: `docs/design/dns-cloudflare-setup.md`.
4. Для матрицы совместимости — машины Win10, Win11, Server 2016/2019/2022.
5. Реестр контейнеров для образа платформы (GitHub Packages подойдёт).
6. Код PHP-панели, работающей с `AnibusBase`, — без него размещать нечего.
7. Разбор абьюза на бесплатном хостинге: пока по тому же адресу живут фишинговые
   и похожие на вредоносные домены, блокировка адреса или зоны унесёт вместе с
   ними любой наш сервис, размещённый рядом.
